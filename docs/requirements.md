# NewAPI 渠道同步工具需求梳理

## 1. 背景

GitHub 上存在一个开源项目 NewAPI。当前已经部署了多个 NewAPI 实例，每个实例内可能已有不同数量、不同配置的渠道。

现在希望新增一个独立项目作为统一管理入口，用来维护一份“项目侧渠道”，并把这些渠道按需同步到多个 NewAPI 实例中。

## 2. 目标

建立一个 NewAPI 渠道同步管理工具，支持：

- 添加和管理多个 NewAPI 实例。
- 在本项目内新建渠道。
- 将项目内新建的渠道绑定到一个或多个 NewAPI 实例。
- 将项目侧渠道单向同步到已绑定的 NewAPI 实例。
- 支持账号密码登录，登录后使用 JWT 维持会话。
- 区分管理员和普通账号对密钥字段的可见性。

## 3. 非目标

当前阶段不做以下能力，除非后续明确加入：

- 不从 NewAPI 实例反向导入渠道到项目。
- 不以 NewAPI 实例现有渠道作为项目侧的基准数据。
- 不要求多个 NewAPI 实例之间互相直接同步。
- 不自动删除实例上已有但项目侧不存在的渠道。
- 不自动覆盖实例上与本项目无绑定关系的既有渠道。
- 不直接依赖 NewAPI 管理后台管理员接口作为一期同步通道。

## 4. 核心同步模型

### 4.1 数据流向

同步方向固定为：

```text
项目侧渠道 => newapi1 / newapi2 / ...
```

也就是说，项目侧是主数据源，NewAPI 实例是下游目标。

### 4.2 实例已有渠道处理

假设：

- newapi1 当前已有 10 个渠道。
- newapi2 当前已有 20 个渠道。

这些既有渠道不纳入项目侧管理，也不影响项目侧同步逻辑。

项目只关心在本项目中新建的渠道，以及这些渠道与目标 NewAPI 实例之间的绑定关系。

### 4.3 渠道绑定

项目侧新建渠道后，需要建立绑定关系，例如：

```text
项目渠道 A -> newapi1
项目渠道 A -> newapi2
项目渠道 B -> newapi2
```

只有已经绑定的目标实例才会收到该渠道的同步。

### 4.4 同步行为

初始理解：

- 项目中新建渠道后，可以同步创建到绑定的 NewAPI 实例。
- 项目侧修改一个已绑定渠道后，可以同步更新到对应 NewAPI 实例。
- 同步只影响由本项目创建或绑定管理的远端渠道。
- 同步结果需要保存远端实例返回的渠道 ID 或等价标识，用于后续更新。

删除、禁用、覆盖、重试等行为需要进一步明确。

### 4.5 同步通道

同步采用 NewAPI 用户 MCP 的方式执行。

当前理解：

- 每个 NewAPI 实例在本项目中保存一套用户侧 MCP 连接信息。
- 本项目通过该 MCP 通道调用 NewAPI 实例提供的渠道相关能力。
- 本项目不直接使用 NewAPI 管理后台页面操作，也不把管理员后台接口作为一期主路径。
- MCP 调用成功后，需要返回或可查询到远端渠道 ID 或等价标识，用于维护项目渠道与实例渠道的绑定关系。
- 本项目内的“管理员/普通用户”只控制本项目权限；NewAPI 侧 MCP 用户权限由 NewAPI 实例自身控制。

MCP 具体工具名称、入参、返回结构和鉴权方式需要进一步确认。

## 5. 用户与权限

### 5.1 登录

系统支持：

- 账号密码登录。
- 登录成功后签发 JWT。
- 后续接口通过 JWT 鉴权。

### 5.2 角色

至少包含两类角色：

- 管理员账号。
- 普通账号。

### 5.3 密钥可见性

渠道同步涉及密钥字段，例如 API Key、渠道 Key 或上游供应商 Key。

当前理解：

- 管理员可以查看项目侧保存的密钥明文或可恢复密钥。
- 普通账号在创建或同步密钥后，不能再在项目页面看到密钥内容。
- 普通账号可以看到密钥存在状态，例如“已配置”。

密钥是否允许普通账号创建、修改、重置，需要进一步确认。

## 6. 建议的一期功能范围

### 6.1 实例管理

- 新增 NewAPI 实例。
- 编辑实例名称、基础地址、用户 MCP 连接信息。
- 测试实例 MCP 连接。
- 查看实例状态。
- 禁用或删除实例。

### 6.2 渠道管理

- 新建项目侧渠道。
- 编辑项目侧渠道。
- 查看渠道列表。
- 绑定渠道到一个或多个 NewAPI 实例。
- 查看渠道在各实例上的同步状态。

### 6.3 同步管理

- 手动触发单个渠道同步。
- 手动触发批量同步。
- 记录每次同步结果。
- 展示同步成功、失败、待同步、部分成功等状态。
- 失败时记录错误原因。

### 6.4 账号权限

- 管理员创建和管理用户。
- 用户账号密码登录。
- JWT 会话鉴权。
- 管理员可查看密钥。
- 普通用户不可查看密钥明文。

## 7. 数据对象草案

### 7.1 NewAPI 实例

建议字段：

- 实例 ID。
- 实例名称。
- 实例基础 URL。
- MCP 服务地址。
- MCP 鉴权方式。
- MCP 用户凭据或访问令牌。
- 启用状态。
- 最近连接检查时间。
- 最近连接检查结果。

### 7.2 项目侧渠道

建议字段：

- 渠道 ID。
- 渠道名称。
- 渠道类型。
- 模型配置。
- 密钥或密钥引用。
- 渠道状态。
- 创建人。
- 创建时间。
- 更新时间。

### 7.3 渠道实例绑定

建议字段：

- 绑定 ID。
- 项目渠道 ID。
- NewAPI 实例 ID。
- 远端渠道 ID。
- 最近同步状态。
- 最近同步时间。
- 最近同步错误。

### 7.4 用户

建议字段：

- 用户 ID。
- 用户名。
- 密码哈希。
- 角色。
- 启用状态。
- 最近登录时间。

## 8. 待明确的模糊需求

### 8.1 NewAPI 版本、MCP 与接口

需要确认：

- 当前部署的 NewAPI 是哪个开源仓库、哪个版本或 commit。
- NewAPI 用户 MCP 是内置能力、插件能力，还是需要在每个实例额外部署。
- 每个 NewAPI 实例的 MCP 服务地址如何配置。
- MCP 鉴权方式是什么，是用户 token、JWT、API Key，还是其他机制。
- MCP 用户需要具备哪些权限才能新增、更新、启用、禁用渠道。
- MCP 是否提供稳定的渠道管理工具或方法。
- 添加、更新、删除、启用、禁用渠道分别对应哪些 MCP 工具或接口。
- MCP 调用后是否返回远端渠道 ID，或是否需要再调用查询接口获得。
- 如果 MCP 只支持部分渠道操作，一期功能边界需要随之收缩。

### 8.2 渠道字段范围

需要确认一期要支持哪些 NewAPI 渠道字段，例如：

- 渠道名称。
- 渠道类型。
- Base URL。
- API Key。
- 模型映射。
- 分组。
- 权重。
- 优先级。
- 额度、倍率、状态。
- 其他 NewAPI 特有字段。

如果字段很多，建议一期先支持必要字段，其他字段允许以 JSON 扩展配置保存。

### 8.3 同步创建还是同步更新

当前描述明确了“新建渠道同步”，但以下场景需要确认：

- 项目侧渠道修改后，是否要更新所有绑定实例。
- 项目侧渠道删除后，是否要删除远端实例渠道。
- 项目侧渠道禁用后，是否要禁用远端实例渠道。
- 如果远端实例上对应渠道被人工修改，项目侧下次同步是否强制覆盖。
- 如果远端实例上对应渠道被人工删除，项目侧下次同步是重新创建还是报错。

### 8.4 绑定规则

需要确认：

- 一个项目渠道是否可以绑定多个实例。
- 一个项目渠道在同一个实例上是否只能对应一个远端渠道。
- 绑定是创建渠道时选择，还是创建后再选择。
- 是否需要支持默认绑定到全部实例。
- 是否需要支持按实例分组批量绑定。

### 8.5 去重规则

需要确认：

- 项目侧是否允许同名渠道。
- 同一个实例里，如果已经存在同名渠道但不是本项目创建的，是否忽略、复用、报错，还是创建新渠道。
- 判断“同一个渠道”的依据是项目绑定表、远端渠道 ID、渠道名称，还是自定义标记。

建议一期以“绑定表保存的远端渠道 ID”为准，不依赖渠道名称判断。

### 8.6 密钥存储与展示

需要确认：

- 密钥是否必须可被系统解密后再次同步。
- 密钥是明文加密存储，还是只保存不可逆哈希。
- 管理员是否真的需要查看完整明文密钥，还是只需要重置能力。
- 普通用户是否可以输入或更新密钥。
- 日志、错误信息、接口响应中是否必须脱敏密钥。

如果系统需要把密钥同步给 NewAPI，项目侧通常必须保存可解密密文，不能只保存哈希。

### 8.7 用户权限边界

需要确认：

- 普通账号是否可以创建渠道。
- 普通账号是否可以绑定实例。
- 普通账号是否可以触发同步。
- 普通账号是否可以新增或编辑 NewAPI 实例。
- 普通账号是否可以查看同步失败原因。
- 是否需要按项目、实例、渠道做更细粒度权限。

### 8.8 同步触发方式

需要确认：

- 一期是否只需要手动同步。
- 是否需要定时同步。
- 是否需要保存同步任务队列。
- 同步失败是否自动重试。
- 是否需要并发控制，避免多个同步任务同时修改同一远端渠道。

建议一期先做手动同步和失败记录，后续再加定时任务与队列。

### 8.9 MCP 同步通道细节

需要确认：

- MCP 是长连接、HTTP 调用，还是通过本地/远程 MCP Server 中转。
- 本项目是否直接作为 MCP Client 连接各 NewAPI 实例。
- 每个 NewAPI 实例是否需要单独配置 MCP 用户。
- MCP 用户凭据是否允许长期保存，是否支持刷新。
- MCP 调用失败时的错误码、错误消息是否稳定。
- MCP 是否有速率限制、并发限制或操作审计。
- MCP 请求和响应中是否会包含密钥明文，日志必须如何脱敏。

### 8.10 审计与日志

需要确认：

- 是否记录谁创建、修改、同步了渠道。
- 是否记录密钥变更事件。
- 是否允许管理员查看同步请求和响应摘要。
- 日志保留多久。
- 是否需要导出日志。

### 8.11 部署方式

需要确认：

- 项目部署在单机、Docker Compose、Kubernetes，还是现有服务器上。
- 数据库使用 SQLite、PostgreSQL、MySQL 还是其他。
- 是否需要多环境配置，例如 dev、staging、prod。
- 是否需要前后端分离。

### 8.12 技术栈

需要确认：

- 后端语言和框架偏好。
- 前端框架偏好。
- 是否已有内部模板或基础项目。
- 是否需要 OpenAPI 文档。
- 是否需要对接现有 SSO 或用户系统。

## 9. 建议的优先级

### P0

- 私有部署。
- 管理员登录。
- NewAPI 实例管理。
- 项目侧渠道创建。
- 渠道绑定实例。
- 通过 NewAPI 用户 MCP 单向手动同步创建渠道。
- 同步状态记录。
- 密钥对普通用户脱敏。

### P1

- 渠道更新同步。
- 批量同步。
- 普通用户权限。
- 同步失败重试。
- 审计日志。

### P2

- 定时同步。
- 实例分组。
- 批量导入渠道。
- 更细粒度 RBAC。
- 同步差异预览。

## 10. 当前推荐的一期边界

为了降低实现风险，建议一期先定义为：

- 项目侧只管理本项目创建的渠道。
- 不导入、不删除、不清理 NewAPI 实例已有渠道。
- 手动触发同步。
- 同步时通过 NewAPI 用户 MCP 只创建或更新绑定表内可识别的远端渠道。
- 密钥加密存储，普通用户只看脱敏状态，管理员可查看或重置。
- 所有同步动作写入日志。
